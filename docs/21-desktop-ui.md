# پوستهٔ دسکتاپ (M1-lite) — متریال «Liquid Glass»

> **یک خط:** یک پنجرهٔ شیشه‌ای واقعی روی همان هستهٔ C++، با اعداد سنجش زنده؛
> هر دکمهٔ «پردازش» یک فرایند واقعی `atlas-cli` را اجرا می‌کند — نه شبیه‌سازی.

**تاریخ:** ۲۰۲۶-۱۱-۱۱ · **کد:** `desktop/` (`server.py`، `web/index.html`، `web/styles.css`،
`web/app.js`) · **تست:** `desktop/test_server.py` — ۷ تست دودی، همه سبز

---

## ۱) زبان بصری: از مرجع تا پیاده‌سازی

مرجع طراحی، تصویری از Liquid Glass اپل (Icon Composer، WWDC25) بود. آن زبان بصری
به‌صورت متریال CSS پیاده شد، نه به‌صورت کپی تصویر:

| ویژگی در مرجع | پیاده‌سازی ما |
|---|---|
| پنل‌های شیشه‌ای شیری روی پس‌زمینهٔ آبی | `backdrop-filter: blur(34px) saturate(165%)` + گرادیان سفید ۰٫۶۲→۰٫۳۴ |
| لبهٔ نورانی و بازتاب داخلی | `border: 1px solid rgba(255,255,255,.42)` + `inset 0 1px 0 rgba(255,255,255,.85)` |
| پس‌زمینهٔ اقیانوسی با هاله‌های نرم | چهار `radial-gradient` + سه «bloom» با `filter: blur(70px)` و `mix-blend-mode: screen` |
| نوار نور مایل | یک `linear-gradient` چرخیده با `blur(38px)` |
| ردیف‌های کنترل با سوییچ و مقدار | ردیف شیشه‌ای ۳۸px + سوییچ iOS + اسلایدر با شیار گرادیانی و پلاک مقدار |
| چراغ‌های پنجرهٔ مک | سه دایرهٔ گرادیانی با سایهٔ داخلی (تزئینی، بدون رفتار بستن) |

هیچ تصویر یا فونت خارجی بارگذاری نمی‌شود: پس‌زمینه تماماً CSS است و فونت از
پشتهٔ سیستمی (`Vazirmatn` → `SF Pro Text` → `Noto Sans Arabic` → `system-ui`).
این هم با اصل «آفلاین» پروژه سازگار است و هم صفحه در شبکهٔ بدون اینترنت کامل است.

## ۲) معماری (و چرا این‌طور)

```text
مرورگر/WebView ──HTTP──▶ desktop/server.py ──subprocess──▶ atlas-cli (C++)
   (HTML/CSS/JS)          (فقط stdlib)                      هستهٔ واقعی
```

- **UI بدون build**: نه npm، نه bundler، نه مرحلهٔ کامپایل. سه فایل + یک سرور.
- **پل، فرایند است نه FFI**: اگر پردازش کرش کند، پنجره نمی‌میرد؛ و هر کاری که UI
  می‌کند با همان دستور در ترمینال قابل بازتولید است (برای دیباگ و گزارش).
- **اعداد از هسته می‌آیند**: `restore --json` می‌دهد `sigma_before/after`،
  `blockiness_before/after`، شدت‌های خودکار و زمان. UI هیچ عددی را نمی‌سازد.
- **دو مرحله، دو فرایند**: ابتدا `restore` (پاک‌سازی)، بعد در صورت نیاز
  `enhance --scale N` روی خروجی پاک‌شده. دقیقاً همان ترتیبی که در
  [docs/20](20-degrade-restore.md) اندازه‌گیری شد (+۴٫۱۷ dB).
- **حریم خصوصی**: سرور فقط روی `0.0.0.0:<port>` همین دستگاه گوش می‌دهد، هیچ
  درخواست بیرونی ندارد، و دادهٔ کار در `desktop/.data/` می‌ماند (در گیت نیست).

## ۳) آنچه در UI واقعاً کار می‌کند

| کنترل | رفتار واقعی |
|---|---|
| کشیدن/انتخاب فایل | آپلود محلی + ساخت پیش‌نمای PNG (orientation و ICC اعمال می‌شود) |
| «۱×…۴×» | مقیاس بزرگ‌نمایی؛ ۱× یعنی فقط پاک‌سازی |
| «پاک‌سازی: خودکار/دستی/خاموش» | خودکار = σ و نسبت بلوک از خود تصویر؛ دستی = درصدهای اسلایدر |
| سوییچ نویز / بلوک | خاموش‌کردن هر مرحله (`--denoise off` / `--deblock off`) |
| «مقایسه» + دستهٔ کشیدنی | مقایسهٔ قبل/پس با `clip-path`؛ با کلیدهای ← → هم جابه‌جا می‌شود |
| «سنجش» | σ، blockiness، زمان و ابعاد — از JSON هسته |
| «دانلود نتیجه» | فایل PNG خروجی با نام اصلی + پسوند مقیاس |

**اجرا:** `python desktop/server.py --port 8000` (یا `--open` که خودش مرورگر را
باز می‌کند) و بعد `http://localhost:8000`. آدرسی که چاپ می‌شود `0.0.0.0` است چون
سرور روی همهٔ اینترفیس‌ها گوش می‌دهد؛ در مرورگر `localhost` را بزنید.

نمونهٔ واقعی (همین محیط، ۲ هستهٔ CPU): تصویر ۴۸۰×۳۶۰ JPEG کیفیت ۲۰ →
پاک‌سازی + ۲× در **۰٫۴۱ ثانیه**، خروجی ۹۶۰×۷۲۰، σ از ۰٫۰۰۲۶ به ۰٫۰۰۰۸.

## ۴) تست

```bash
python3 desktop/test_server.py        # ۷ تست سرور (فقط stdlib)
# Ran 7 tests … OK

cd desktop && npm install && npm run test:dom   # ۱۸ بررسی DOM (اختیاری، jsdom)
# همهٔ بررسی‌های DOM سبز است.
```

**تست سرور** (بدون هیچ وابستگی): سلامت سرور و مسیر CLI، سرو صفحه، آپلود PNG و
خواندن ابعاد، پردازش با مقیاس ۲ (۹۶×۶۴) و مقیاس ۱ (بدون تغییر ابعاد)، دریافت
واقعی بایت‌های PNG، ردّ پسوند غیرمجاز (۴۰۰)، آیتم ناموجود (۴۰۴).

**تست DOM** (وابستگی توسعه‌ای اختیاری، `jsdom`): رندر فهرست، شمارندهٔ فارسی،
انتخاب آیتم، خواندن σ/زمان/ابعاد از پاسخ API، نشان دستگاه، پیش‌نماها، فعال/غیرفعال
شدن دانلود، رفتار «مقایسه» بدون نتیجه، ارسال درست بدنهٔ `/api/process`، و
حالت‌های خودکار/دستی/خاموش در کنترل‌های پاک‌سازی.

این تست‌ها در کنار ۷۱ تست هسته اجرا می‌شوند. هیچ‌کدام — به‌جز تست DOM — به
مرورگر یا npm نیاز ندارند؛ ساخت خود پروژه هنوز صفر-وابستگی است.

## ۵) محدودیت‌های صادقانه

0. **مسیر ویندوز:** `tools/windows/build.bat` و `tools/windows/run-desktop.bat` اضافه شدند؛
   سرور هم `build\Release\atlas-cli.exe` و `build\atlas-cli.exe` را می‌شناسد. راهنمای
   کامل: `tools/windows/README.md`.
1. **این Tauri/نیتیو نیست.** یک وب‌اپ محلی است که در مرورگر باز می‌شود. بستهٔ
   `.exe`/`.dmg`/`.apk` هنوز ساخته نشده و در این محیط (بدون Rust/WebKit) هم
   ساخته نمی‌شود. مسیر مهاجرت در `desktop/README.md` آمده است.
2. **بدون پیشرفت زنده.** نوار «در حال پردازش…» چرخان است اما درصد کاشی‌ها
   استریم نمی‌شود؛ برای فایل‌های بزرگ باید صبر کرد.
3. **یک کار در لحظه.** `atlas-cli` با قفل سراسری اجرا می‌شود؛ دکمهٔ دوم منتظر
   می‌ماند. دستهٔ واقعی (queue) کار بعدی است.
4. **دروازهٔ هویت در UI نیست.** `atlas-cli gate` وجود دارد ولی پنل چهره/گیت
   هنوز به رابط اضافه نشده.
5. **مرورگرهای قدیمی** بدون `backdrop-filter` ظاهر شیشه‌ای را از دست می‌دهند
   (عملکرد سالم است، زیبایی نه).
6. **بدون تست بصری خودکار.** در این محیط مرورگر نصب نیست، پس اندازه‌گیری
   «چشم‌نواز بودن» عینی نیست؛ باید خودتان ببینید و بگویید کجایش را تغییر دهم.

## 📝 یادداشت من (پایان این فایل)

**تاریخ:** ۲۰۲۶-۱۱-۱۱ · **فایل:** `docs/21-desktop-ui.md`

- **آنچه مسلم شد:** «تم» فقط رنگ نیست؛ سه چیز آن حس را می‌سازد: بلور پس‌زمینه،
  لبهٔ نورانی داخلی، و هاله‌های نرم پشت پنجره. با CSS خالص می‌شود، بدون تصویر.
- **تصمیم:** UI هیچ محاسبه‌ای نمی‌کند؛ همهٔ اعداد از JSON هسته می‌آیند. اگر روزی
  عدد UI با ترمینال فرق کرد، باگ است، نه تنظیم.
- **ریسک:** وب‌اپ محلی به‌عنوان «اپ دسکتاپ» پذیرفته نشود. راه‌حل، Tauri است با
  همین فایل‌ها؛ عمداً چیزی در UI به مرورگر گره نخورد.
- **بدون تست بصری:** در این محیط مرورگر نیست؛ تنها راه قضاوت، چشم کاربر است.
- **قدم بعدی:** بازخورد بصری کاربر، بعد Tauri یا صف دسته‌ای.
