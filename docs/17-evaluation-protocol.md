# ۱۷ — پروتکل ارزیابی کیفیت، هویت و انصاف

> «قوی‌ترین» بدون اندازه‌گیری، ادعاست. این سند تعریف می‌کند چه چیزی، چطور، با چه آستانه‌ای و توسط چه کسی سنجیده می‌شود.

---

## ۱. مجموعهٔ طلایی (Golden Set)

### ۱.۱ ترکیب پیشنهادی: ۳۰۰ تصویر

| گروه | تعداد | تنوع اجباری |
|---|---|---|
| پرترهٔ تکی | ۱۰۰ | تیپ پوستی I–VI، سن ۵–۸۰، عینک/ریش/آرایش، روبه‌رو/نیم‌رخ، نور طبیعی/مصنوعی/شب |
| گروهی | ۵۰ | ۲–۱۲ نفر، چهرهٔ ۲۰–۲۰۰px، پشت‌سرهم |
| کم‌نور/نویزی | ۴۰ | ISO بالا، فلاش، موبایل قدیمی |
| فشرده‌شده (شبکهٔ اجتماعی) | ۴۰ | واتساپ/تلگرام/اینستاگرام، q پایین، چند بار recompress |
| عکس قدیمی/B&W | ۳۰ | خش، پارگی، رنگ‌رفتگی |
| اسکرین‌شات/مورا | ۲۰ | عکس از صفحه، متن روی تصویر |
| آرت/انیمه (کنترل منفی) | ۲۰ | برای اطمینان از انتخاب مدل درست |

### ۱.۲ قواعد مجموعه

- هر تصویر: نسخهٔ اصلی با کیفیت بالا (در صورت وجود) به‌عنوان مرجع + نسخهٔ تخریب‌شدهٔ واقعی.
- ۵۰٪ تصاویر باید «واقعی تخریب‌شده» باشند، نه مصنوعی.
- هیچ تصویری از مجموعه در آموزش استفاده نشود (نشت داده).
- متادیتای مجموعه: منبع، رضایت، تیپ پوستی (تخمینی)، اندازهٔ چهره، نوع تخریب.
- لایه‌بندی: هر گزارش باید تفکیک‌شده بر اساس تیپ پوستی، سن، اندازهٔ چهره و نوع تخریب باشد.

## ۲. متریک‌ها

### ۲.۱ هویت

| متریک | تعریف | جهت | کاربرد |
|---|---|---|---|
| **IDS-src** | `cos(ArcFace(out), ArcFace(src))` | ↑ | وفاداری به منبع |
| **IDS-ref** | `cos(ArcFace(out), ArcFace(ref))` | ↑ | حالت Reference |
| **IDS-GT** | `cos(ArcFace(out), ArcFace(ground truth))` | ↑ | فقط وقتی GT داریم |
| **LMD** | میانگین فاصلهٔ ۶۸ لندمارک نرمال‌شده | ↓ | حفظ هندسه |
| **Same-person@human** | درصد «همان شخص» در داوری کور | ↑ | مرجع نهایی |

> نقد مهم: استفاده از ArcFace هم برای آموزش و هم ارزیابی، نتیجه را خوش‌بین می‌کند. راه‌حل: **گزارش دو مدل** (ArcFace و AdaFace/MagFace) + داوری انسانی.

### ۲.۲ کیفیت ادراکی و واقع‌گرایی

| متریک | تعریف | جهت |
|---|---|---|
| LPIPS (AlexNet/VGG) | فاصلهٔ ادراکی به مرجع | ↓ |
| DISTS | فاصلهٔ ساختاری-بافتی | ↓ |
| FID / KID | فاصلهٔ توزیع | ↓ |
| NIQE / BRISQUE | کیفیت بدون مرجع | ↓ |
| MUSIQ / CLIPIQA / MANIQA | کیفیت ادراکی بدون مرجع | ↑ |
| HF-Energy Ratio | نسبت انرژی فرکانس بالا به مرجع (بافت) | ≈۱ |
| Artifact Rate | درصد تصاویر با آرتیفکت شدید (داوری) | ↓ |

### ۲.۳ رنگ و انصاف

| متریک | تعریف | آستانه |
|---|---|---|
| ΔE2000 پوست | اختلاف رنگ ناحیهٔ پوست با منبع | < ۳ |
| Skin-lightening Bias | میانگین روشن‌شدن پوست (L*) | ≈۰ (|Δ|<۲) |
| ΔE بین تیپ‌های پوستی | اختلاف عملکرد بین گروه‌ها | < ۲۰٪ نسبی |
| Saturation Drift | تغییر اشباع پوست | < ۵٪ |

### ۲.۴ کارایی

زمان، اوج RAM/VRAM، و زمان تا پیش‌نمایش (جزئیات در `07-performance.md`).

## ۴. پروتکل داوری انسانی

### ۴.۱ طراحی

- **۳ داور** با پیش‌زمینهٔ متفاوت: عکاس/رتوشور، کاربر عادی، متخصص ML.
- **کور**: هیچ برچسبی از روش/مدل نمایش داده نمی‌شود؛ ترتیب تصادفی.
- **مقایسهٔ جفتی اجباری** (A/B) + گزینهٔ «هیچ‌کدام/مساوی».
- **آزمون «همان شخص؟»** با نمایش منبع در کنار خروجی (۳ ثانیه، بدون زوم).
- **مقیاس آرتیفکت** ۱–۵ (۱ = فاجعه، ۵ = بی‌عیب).
- **زوم ۱۰۰٪** برای ارزیابی بافت پوست/مو/چشم.

### ۴.۲ حجم و اعتبار

- حداقل ۶۰ تصویر × ۳ داور برای هر مقایسهٔ اصلی.
- محاسبهٔ توافق: Krippendorff's α؛ هدف > ۰٫۶ (در غیر این صورت پروتکل بازنگری شود).
- گزارش: میانگین + بازهٔ اطمینان ۹۵٪ (bootstrap).

### ۴.۳ پرسش‌های استاندارد

1. کدام تصویر طبیعی‌تر است؟
2. کدام تصویر به منبع وفادارتر است؟
3. آیا این همان شخص است؟ (بله/نه/مطمئن نیستم)
4. آیا آرتیفکت می‌بینی؟ (کجا؟)
5. اگر چاپ کنی، کدام را انتخاب می‌کنی؟

## ۶. ارزیابی «توهم» (Hallucination)

سه روش مکمل:

1. **اختلاف اجراها**: دو seed/دو مدل → نواحی با اختلاف بالا = نامطمئن.
2. **آنالیز فرکانسی**: انرژی بالا در نواحی بی‌بافت (آسمان، دیوار) = بافت جعلی.
3. **آزمون انسانی هدفمند**: «آیا این جزئیات در منبع بود؟» روی ۲۰ ناحیهٔ مشکوک.

خروجی: نقشهٔ اطمینان + هشدار در UI + شمارش در گزارش QA.

## ۷. انصاف (Fairness)

| محور | روش |
|---|---|
| تیپ پوستی I–VI | حداقل ۱۰ چهره در هر تیپ؛ گزارش تفکیک‌شده |
| سن | ۵–۱۷، ۱۸–۴۰، ۴۱–۶۵، ۶۶+ |
| جنسیت ارائه‌شده | حداقل ۴۰٪ هر گروه |
| عینک/ریش/حجاب | زیرگروه‌های جدا |
| نور | روشن/معمولی/کم‌نور |

**قاعدهٔ سخت:** هیچ مدلی که در هر زیرگروه، `Same-person` کمتر از ۹۰٪ یا ΔE پوست > ۴ دارد، منتشر نمی‌شود.

## ۸. یکپارچه‌سازی با CI (تست رگرسیون)

```bash
# در CI روی CPU (مسیر deterministic)
atlas-bench eval \
  --golden tests/golden \
  --preset natural-4x \
  --metrics ids,lpips,dists,niqe,artifact \
  --baseline bench/results/baseline.json \
  --fail-on "ids_median < baseline-0.02" \
  --fail-on "lpips > baseline*1.05"
```

قواعد CI:

- رگرسیون هویت > ۲٪ = شکست.
- رگرسیون LPIPS > ۵٪ = شکست.
- افزایش نرخ آرتیفکت > ۱ واحد درصد = شکست.
- هر مدل جدید باید یک ردیف در `bench/results/` داشته باشد.
