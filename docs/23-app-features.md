## ۲) Light AI — چه چیزی و چرا این‌طور

«Light AI» در LetsEnhance یک شبکهٔ عصبی برای نور/رنگ است. ما در این فاز **مدل
نور** را عمداً مدل نکردیم: یک منحنی ریاضی **یکنوا** پیاده شد که رفتارش قابل
پیش‌بینی و قابل تست است. دلیل در `docs/14` هم آمده: هر مرحله‌ای که پیکسل
«اختراع» می‌کند باید مدل + ارزیابی داشته باشد؛ نور و رنگ نیازی به اختراع پیکسل ندارد.

ترتیب اجرا (و دلیلش):

```text
۱) تعادل رنگ        در نور خطی، گین هر کانال (۰٫۸۵..۱٫۲) — فیزیکی درست
۲) نوردهی + گرمی    ضربی در نور خطی: ۲^EV ، گرمی = ±۱۰٪ قرمز/آبی
۳) سایه‌ها           گاما روی luma:  y^(1/(1+0.9·s))  → سیاه و سفید سر جایشان
۴) هایلایت‌ها        هدف y^γ با ماسک y⁴ (فقط نواحی روشن، ضریب ۱٫۵)
۵) کنتراست          S خطی حول ۰٫۵:  y' = ۰٫۵ + (y−۰٫۵)(۱+۰٫۹c)
۶) اشباع            حول luma پس از منحنی:  rgb' = y + (rgb−y)(1+s)
```

- **چرا گاما برای سایه‌ها؟** ضرب خطی، سیاهِ مطلق را خاکستری می‌کند؛ `y^g` با
  `g<۱` سایه‌ها را بالا می‌آورد ولی `۰` و `۱` را دقیقاً نگه می‌دارد (تست شده).
- **چرا ماسک `y⁴` برای هایلایت؟** با `y²` اثر روی میانه‌ها هم می‌افتاد (نسبت
  اثر روشن/میانه فقط ۱٫۲۶ بود)؛ با `y⁴` نسبت به ۳٫۷ رسید و میانه دست‌نخورده ماند.
- **خنثی یعنی خنثی:** اگر همهٔ گزینه‌ها صفر باشند، تابع تصویر را **بیت‌به‌بیت**
  برمی‌گرداند (بدون رفت‌وبرگشت sRGB↔خطی). `light_neutral_is_bit_exact` این را قفل می‌کند.
- **آلفا هرگز** تغییر نمی‌کند (`light_alpha_is_untouched`).

### اعداد اندازه‌گیری‌شده (این دستگاه، CPU، تصویر ۴۸۰×۳۶۰ ساختگی با بافت)

| سناریو | قبل | بعد |
|---|---|---|
| عکس زیرنور (`auto-light`) | mean ۰٫۱۴۲ · p50 ۰٫۱۳۶ | mean ۰٫۲۲۳ · p50 ۰٫۲۱۵ (EV = ۱٫۲) |
| تصویر کم‌کنتراست (`auto-light`) | contrast ۰٫۰۵۴۵ | contrast ۰٫۰۶۶۲ (+۲۱٪) |
| عکس سالم با کست آبی (`--auto-wb`) | گین‌ها ۱٫۰۰ | R ۰٫۹۳ / G ۱٫۱۱ / B ۰٫۸۲ · روشنایی تقریباً ثابت |
| ۱۲ مگاپیکسل، ۵ عملیات | — | **۱٫۷۵ ثانیه** (تک‌رشته) |

این اعداد «اثر» را نشان می‌دهند، نه «کیفیت نهایی»؛ داوری کیفیت با مجموعهٔ طلایی
(`docs/17`) انجام می‌شود، نه با این جدول.

## ۴) صف دسته‌ای: پیشرفت از کجا می‌آید؟

`atlas-cli enhance` در حین کار `tiles : 7/24 (29%)` را روی خروجی می‌نویسد.
سرور همان خط را می‌خواند (بدون هیچ درصد ساختگی) و آن را به بازهٔ ۳۰–۹۵٪ مرحلهٔ
بزرگ‌نمایی نگاشت می‌کند؛ ۰–۳۰٪ پاک‌سازی/نور، ۹۵–۱۰۰٪ ذخیره.

```text
POST /api/jobs {ids:[…], options:{…}}      → ۲۰۲ + job
GET  /api/jobs/<id>                        → status/progress/items[].progress
POST /api/jobs/<id>/cancel                 → کشتن فرآیند در حال اجرا
```

- **یک worker**: پردازش‌ها پشت سر هم اجرا می‌شوند تا CPU به یک عکس نرسد؛
  صف در `/api/jobs` دیده می‌شود و در `state.json` نمی‌نشیند (موقت است).
- **خطای یک فایل، صف را نمی‌کشد**: هر آیتم وضعیت `error` و پیام خودش را دارد و
  بقیه ادامه می‌دهند (تست: `job_worker` با `except` جدا).
- **لغو**: `Event` + `process.kill()`؛ آیتم‌های نرسیده `cancelled` می‌شوند.
  روی فایل کوچک ممکن است پیش از رسیدن لغو تمام شود — تست هر دو را می‌پذیرد و
  این محدودیت را صادقانه ثبت می‌کند.

## ۵) خروجی: نام، فرمت، پوشه

- الگوی نام با توکن: `{name}` `{scale}` `{preset}` `{date}` — پیش‌فرض `{name}-{scale}`.
- `{scale}` برای مقیاس ۱ به `clean` تبدیل می‌شود (`عکس-clean.png`)، نه `-1x`.
- فرمت‌ها: PNG، JPEG (با کیفیت)، WebP **فقط اگر** `atlas-cli` با libwebp ساخته
  شده باشد؛ در غیر این صورت گزینه در UI غیرفعال است و API با ۴۰۰ پاسخ می‌دهد
  (به‌جای شکستن در نیمهٔ راه).
- پوشهٔ پیش‌فرض: `desktop/.data/output` در توسعه، `%LOCALAPPDATA%\Atlas\data\output`
  در نسخهٔ بسته‌بندی‌شده. هر مسیری قابل تنظیم است.
- دانلود در حالت مرورگری فقط از داخل پوشهٔ داده/خروجی سرو می‌شود
  (`/api/download?path=…`، تست ۴۰۳ برای `/etc/passwd`).

## ۶) API محلی (برای هر کسی که بخواهد اسکریپت بزند)

| مسیر | کار |
|---|---|
| `GET /api/health` | وضعیت CLI، قابلیت‌ها، تنظیمات، فهرست تصاویر، صف‌های فعال |
| `GET /api/capabilities` | نسخه، `webp`، `ncnn`، تعداد هسته، فرمت‌ها، پریست‌ها |
| `GET/POST /api/settings` | خواندن/ذخیرهٔ تنظیمات (ماندگار) |
| `POST /api/upload?name=` | آپلود؛ پیش‌نمای PNG با orientation/ICC درست ساخته می‌شود |
| `POST /api/process` | پردازش همگام یک تصویر |
| `POST /api/jobs` | صف دسته‌ای |
| `GET /api/jobs`، `GET /api/jobs/<id>` | وضعیت صف |
| `POST /api/jobs/<id>/cancel` | لغو |
| `POST /api/export` | ذخیرهٔ نتیجه‌های موجود با فرمت/نام/پوشهٔ دلخواه |
| `DELETE /api/item/<id>` | حذف تصویر و فایل‌هایش |
| `GET /api/download?path=` | دانلود امن خروجی (محدود به پوشهٔ داده) |
| `GET /img/<id>/<file>?v=` | پیش‌نمای قبل/بعد |
| `GET /api/devices` | دستگاه‌ها از خود هسته |

بدنهٔ `/api/process` و `/api/jobs`:

```json
{
  "scale": 2, "quality": 92, "format": "png",
  "denoise": "auto", "deblock": "auto",
  "light": {"exposure": 0, "contrast": 0, "saturation": 0,
            "shadows": 0, "highlights": 0, "warmth": 0},
  "auto_light": true, "auto_wb": true, "light_mode": "auto",
  "tile": 256, "threads": 0, "keep_metadata": false,
  "pattern": "{name}-{scale}", "output_dir": "", "preset": "photo", "export": true
}
```

## ۷) CLI تازه

```bash
# فقط نور و رنگ (هندسه دست نمی‌خورد)
./build/atlas-cli adjust in.jpg out.png --auto-light --auto-wb --json
./build/atlas-cli adjust in.jpg out.png --exposure 0.4 --shadows 0.3 \
      --highlights -0.3 --saturation 0.2 --warmth 0.15

# نور پیش از بزرگ‌نمایی (در همان فرآیند)
./build/atlas-cli enhance in.jpg out4x.png --scale 4 --auto-light --auto-wb --json

# قابلیت‌های build
./build/atlas-cli version --json
# {"version":"0.2.0-dev","ncnn":false,"webp":false,"threads":2}
```

## ۸) آنچه صادقانه *هنوز* نیست

1. **بدون مدل SR**: مسیر پیش‌فرض کلاسیک (Lanczos + unsharp) است. بزرگ‌نمایی
   واقعیِ بافتی به `-DATLAS_WITH_NCNN=ON` + وزن‌ها نیاز دارد (`tools/fetch_models.py`).
2. **بدون بازسازی چهره و بدون حذف پس‌زمینه**: این‌ها مدل می‌خواهند و در فاز P3/M2
   با دروازهٔ هویت وصل می‌شوند (`docs/15`، `docs/19`).
3. **تعادل رنگ خودکار تقریبی است**: فرض «جهان خاکستری» روی غروب/آسمانِ رنگی
   می‌تواند اشتباه کند؛ به همین دلیل گین‌ها نصف و محدود شده‌اند. اگر صحنه را
   دوست دارید، `auto_wb` را خاموش کنید.
4. **یک worker**: صف موازی نیست. برای CPU چند‌هسته‌ای، `threads` را بالا ببرید،
   نه تعداد worker را.
5. **پیشرفت درشت است**: از تعداد کاشی می‌آید؛ روی عکس‌های کوچک (۱ کاشی) پرش
   از ۳۰٪ به ۹۵٪ طبیعی است.
6. **بدون WebP در build پیش‌فرض ویندوزِ کاربر** (libwebp نصب نیست)؛ گزینه در UI
   غیرفعال است، نه اینکه پنهان شود.
