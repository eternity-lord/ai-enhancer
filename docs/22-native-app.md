# برنامهٔ واقعی ویندوز (Atlas.exe) — پنجرهٔ نیتیو با همان تم

> **یک خط:** همان رابط شیشه‌ای، ولی داخل یک **پنجرهٔ سیستمی** با یک فایل اجرایی
> (`Atlas.exe`) — نه تب مرورگر، نه ترمینال باز.

**تاریخ:** ۲۰۲۶-۱۱-۱۱ · **کد:** `desktop/app.py`، `desktop/build-exe.bat`،
`desktop/server.py` (پشتیبانی از حالت بسته‌بندی‌شده) · **تست:** ۱۲ تست سرور (۳ تست تازه)

---

## ۱) تصمیم معماری

```text
┌──────────────────────────────────────────────┐
│ Atlas.exe (PyInstaller، یک فایل)             │
│                                              │
│  pywebview ── WebView2 (ویندوز) / WebKit     │
│      │            رابط: desktop/web          │
│      │  HTTP روی 127.0.0.1 (پورت تصادفی)     │
│      ▼                                       │
│  server.py (همان سرور آزمایش‌شده)            │
│      │  subprocess                           │
│      ▼                                       │
│  atlas-cli.exe (هستهٔ C++، داخل بسته)         │
└──────────────────────────────────────────────┘
```

| گزینه | چرا نه / چرا بله |
|---|---|
| **Electron** | Chromium کامل (~۲۰۰ MB) و نیاز به Node؛ و در این محیط امکان دریافت باینری Electron نبود. |
| **Tauri** | نیاز به Rust + WebView سیستمی؛ Rust در محیط ساخت نبود. |
| **pywebview + PyInstaller** ✅ | از WebView2 خود ویندوز استفاده می‌کند (روی Win10/11 نصب است)، خروجی تک‌فایل، و همان UI بدون تغییر. |

هیچ منطق پردازشی دوباره نوشته نشد: `app.py` همان `server.py` را در یک thread
بالا می‌آورد و پنجره را به آن وصل می‌کند. یعنی مسیر آزمایش‌شده عوض نمی‌شود و
تفاوت رفتار بین «مرورگر» و «برنامه» فقط در قاب پنجره است.

---

## ۲) ساخت (روی ویندوز)

```bat
:: ۱) هسته
tools\windows\build.bat

:: ۲) برنامهٔ واقعی
desktop\build-exe.bat
```

خروجی: `desktop\dist\Atlas.exe` — یک فایل، بدون کنسول.

داخل بسته چه چیزی هست:

| جزء | نحوهٔ بسته‌بندی |
|---|---|
| رابط شیشه‌ای | `--add-data "web;web"` |
| `atlas-cli.exe` | `--add-binary "..\build\atlas-cli.exe;."` |
| سرور و منطق | `import server` (PyInstaller خودش تحلیل می‌کند) |
| WebView2 DLLها | قلاب رسمی pywebview (`pywebview/__pyinstaller`) |

مسیرها در حالت بسته‌بندی‌شده درست می‌شوند:

```python
bundle_root()  # → sys._MEIPASS   (فایل‌های همراه)
data_dir()     # → %LOCALAPPDATA%\Atlas\data  (کاربر، قابل نوشتن)
cli_candidates # → کنار Atlas.exe، داخل _MEIPASS، سپس build\...
```

## ۳) دو حالت پنجره

| حالت | دستور | ظاهر |
|---|---|---|
| عادی (پیش‌فرض) | `Atlas.exe` | نوار عنوان ویندوز + رابط شیشه‌ای؛ چراغ‌های تزئینی پنهان می‌شوند |
| بدون قاب | `Atlas.exe` با `desktop/app.py --frameless` | فقط شیشه؛ چراغ‌های macOS واقعی می‌شوند (بستن/کوچک/بزرگ) و پنجره از نوار بالای پنل‌ها کشیده می‌شود |

چرا پیش‌فرض، حالت با قاب است؟ چون **بدون قاب، اگر کشیدن پنجره درست کار نکند،
کاربر گیر می‌افتد**. حالت شیشه‌ای آزمایشی است و در `app.py --frameless` یا با
فلگ exe (در نسخه‌های بعد) در دسترس است.

## ۴) لاگ و عیب‌یابی

برنامه با `--noconsole` ساخته می‌شود، پس هیچ پنجرهٔ خطایی ندارد؛ هر خطا در این
فایل نوشته می‌شود:

```text
%LOCALAPPDATA%\Atlas\data\atlas.log
```

برای دیدن خطاها در ترمینال، همین را بزنید (بدون ساخت exe):

```bat
python desktop\app.py --check     :: سلامت بسته: سرور + مسیر atlas-cli
python desktop\app.py --browser   :: همان رابط در مرورگر
python desktop\app.py             :: پنجرهٔ نیتیو
```

## ۵) آنچه واقعاً آزمایش شده (و آنچه نه)

✅ **آزمایش‌شده در این محیط:**

- `python desktop/app.py --check` → `http 200`, `cli=...`, `data=...`, `web=...`
- **شبیه‌سازی حالت بسته‌بندی‌شده**: با `sys.frozen=True` و `sys._MEIPASS` ساختگی،
  `web` از بسته، `data` از پوشهٔ کاربر و `atlas-cli` از بسته پیدا شد؛ `--check` سبز.
- ۱۲ تست سرور، از جمله سه تست تازه: `data_dir` با متغیر محیطی، حالت frozen،
  و حضور مسیر کنار `Atlas.exe` در فهرست کاندیدهای CLI.

❌ **آزمایش‌نشده:**

- **خود `Atlas.exe` ساخته نشد**؛ PyInstaller در این محیط به `libpython3.11.so`
  نیاز دارد که نصب نیست، و اصولاً بستهٔ ویندوزی باید روی ویندوز ساخته شود.
- **رندر پنجره** دیده نشد (این محیط سرور گرافیکی ندارد).
- **حالت بدون قاب** روی ویندوز واقعی آزمایش نشده؛ اگر کشیدن پنجره ناراحت بود،
  حالت پیش‌فرض را استفاده کنید و بگویید تا اصلاح کنم.

## ۶) محدودیت‌های صادقانه

1. **امضای دیجیتال ندارد** → ویندوز SmartScreen ممکن است بار اول هشدار
   «Windows protected your PC» بدهد؛ باید «More info → Run anyway» بزنید.
2. **WebView2 Runtime لازم است.** روی ویندوز ۱۰/۱۱ معمولاً نصب است؛ اگر نبود،
   نصب‌کنندهٔ کوچک Evergreen از مایکروسافت لازم می‌شود.
3. **تک‌فایل بودن، شروع را کند می‌کند** (استخراج در هر اجرا، ۱–۳ ثانیه).
4. **بدون نصب‌کننده**: الان یک `.exe` است، نه MSI/Setup با آیکن منوی شروع.
5. **بدون به‌روزرسانی خودکار.**

## 📝 یادداشت من (پایان این فایل)

**تاریخ:** ۲۰۲۶-۱۱-۱۱ · **فایل:** `docs/22-native-app.md`

- **تصمیم:** به‌جای بازنویسی بک‌اند در Node برای Electron، همان سرور پایتونی
  آزمایش‌شده داخل بسته گذاشته شد. کمترین ریسک، بیشترین بازاستفاده.
- **درس:** «برنامهٔ واقعی» یعنی پنجره و آیکن و دابل‌کلیک؛ ولی زیر آن همان HTTP
  محلی است. این را پنهان نمی‌کنم — در معماری بالا صریح نوشته شده.
- **ریسک:** WebView2 قدیمی/غایب. اگر کاربر خطای صفحهٔ سفید دید، اول همان runtime
  را چک کند؛ لاگ در `%LOCALAPPDATA%\Atlas\data\atlas.log` است.
- **صداقت:** exe در این محیط ساخته نشد؛ فقط منطق مسیرها و سرور با شبیه‌سازی
  frozen آزمایش شد.
