# Atlas Desktop — پوستهٔ دسکتاپ با زبان بصری Liquid Glass

پوستهٔ گرافیکی پروژه: یک پنجرهٔ شیشه‌ای (پنل‌های نیمه‌شفاف، بلور پس‌زمینه، لبهٔ نورانی)
که همهٔ پردازش را **روی همین دستگاه** انجام می‌دهد. هیچ CDN، فونت آنلاین یا آپلود
بیرونی در کار نیست.

```
desktop/
├── server.py        سرور محلی (فقط stdlib) + پل به atlas-cli
├── app.py          پنجرهٔ نیتیو (pywebview) — همان سرور در یک thread
├── test_server.py   ۲۳ تست دودی برای همین سرور
└── web/
    ├── index.html   ساختار سه‌پنلی: کتابخانه / صحنه / بازرس
    ├── styles.css   متریال شیشهٔ مایع + چیدمان واکنش‌گرا
    ├── app.js       آپلود چندتایی، پریست، نور، صف، مقایسه، ذخیره
    └── test_dom.mjs ۴۶ بررسی DOM (اختیاری، jsdom)
```


## چه کارهایی می‌کند؟ (نسخهٔ کامل M1-lite.3)

| بخش | رفتار |
|---|---|
| پریست | ۵ پریست آماده: عکس واقعی ۲×، چاپ ۴×، فقط پاک‌سازی، عکس قدیمی، سبک برای اشتراک |
| پاک‌سازی | خودکار / دستی / خاموش؛ نویز (NLM) و بلوک JPEG هم جدا خاموش‌شدنی |
| نور و رنگ | خودکار یا دستی: روشنایی (EV)، سایه‌ها، هایلایت‌ها، کنتراست، اشباع، گرمی |
| بزرگ‌نمایی | ۱× تا ۴× با کاشی و هم‌پوشانی؛ تعداد کاشی و هسته‌ها قابل تنظیم |
| صف دسته‌ای | «پردازش همه» → نوار پیشرفت واقعی + «لغو» (فرآیند کشته می‌شود) |
| خروجی | PNG/JPEG/WebP (اگر build پشتیبانی کند)، الگوی نام، پوشهٔ دلخواه، بدون بازنویسی |
| حذف | «−» هم فراداده و هم فایل‌ها را برمی‌دارد |
| میان‌بر | `Ctrl+Enter` پردازش، `Ctrl+Shift+Enter` پردازش همه، `Ctrl+S` ذخیره |

اعداد سنجش (σ، بلوک، روشنایی، زمان، مسیر فایل) همه از JSON خودِ هسته می‌آیند.
جزئیات، جدول اعداد و محدودیت‌ها: [docs/23](../docs/23-app-features.md).

## اجرا

```bash
# ۱) هسته را بسازید (اگر نکرده‌اید)
cmake -S core -B build -DCMAKE_BUILD_TYPE=Release && cmake --build build -j

# ۲) سرور محلی را اجرا کنید
python3 desktop/server.py --port 8000
# → http://localhost:8000
```

مسیر `atlas-cli` به‌ترتیب از `ATLAS_CLI`، `build/`، `build-ncnn/`، `build-nowebp/`
پیدا می‌شود. داده‌های کار در `desktop/.data/` می‌مانند (در گیت نیست) و با
`ATLAS_UI_DATA=/path` قابل جابه‌جایی است.

## تست

```bash
python3 desktop/test_server.py     # ۲۳ تست: آپلود، پردازش، نور، صف، ذخیره، حذف، اعتبارسنجی

# اختیاری: ۴۶ بررسی DOM بدون مرورگر (نیاز به یک‌بار npm install)
cd desktop && npm install && npm run test:dom
```

## برنامهٔ واقعی (Atlas.exe) — بدون مرورگر

```bat
tools\windows\build.bat      :: یک‌بار: ساخت هسته
desktop\build-exe.bat        :: ساخت برنامهٔ تک‌فایل
```

خروجی `desktop\dist\Atlas.exe` است: دابل‌کلیک، پنجرهٔ شیشه‌ای باز می‌شود
(WebView2 روی ویندوز). لاگ خطاها: `%LOCALAPPDATA%\Atlas\data\atlas.log`.
جزئیات، معماری و محدودیت‌ها: [docs/22](../docs/22-native-app.md).

حالت توسعه بدون ساخت exe:

```bat
python desktop\app.py             :: پنجرهٔ نیتیو
python desktop\app.py --frameless :: پنجرهٔ بدون قاب (تم کامل، آزمایشی)
python desktop\app.py --browser   :: فقط مرورگر
python desktop\app.py --check     :: سلامت بسته (سرور + مسیر atlas-cli)
```

## چطور استفاده کنم؟ (از پنجره تا خروجی)

۱. در ترمینال:

```bat
python desktop\server.py --port 8000
```

۲. خط `Atlas desktop shell is running → http://localhost:8000` که چاپ شد را در
   مرورگر باز کنید (اگر `--open` بدهید، خودش باز می‌کند). عدد `0.0.0.0` در اولین
   خط فقط «آدرس اتصال» است؛ آدرس واقعی همین `localhost` است.

۳. در رابط:

   - **افزودن عکس:** دکمهٔ «+» در پایین سمت راست، یا کشیدن و رها کردن فایل روی بوم.
   - **انتخاب:** روی تصویر در فهرست کلیک کنید؛ ابعاد و وضعیت زیر نامش می‌آید.
   - **تنظیم:** «بزرگ‌نمایی» (۱× تا ۴×)، «پاک‌سازی» (خودکار/دستی/خاموش),
     «کیفیت» خروجی.
   - **پردازش:** دکمهٔ آبی «پردازش». اعداد σ/بلوک/زمان در پنل «سنجش» پر می‌شوند.
   - **مقایسه:** دکمهٔ «مقایسه» را بزنید و دستهٔ وسط را بکشید (یا ← →).
   - **ذخیره:** «دانلود نتیجه».

۴. برای توقف سرور، در همان ترمینال `Ctrl+C`.

## API محلی

| متد | مسیر | کار |
|---|---|---|
| GET | `/api/health` | وضعیت + مسیر atlas-cli + فهرست تصاویر |
| GET | `/api/devices` | خروجی `atlas-cli devices` |
| POST | `/api/upload?name=…` | بدنهٔ خام تصویر → آیتم جدید + پیش‌نمای PNG |
| POST | `/api/process` | `{id,denoise,deblock,scale,quality}` → نتیجه + متریک‌ها |
| GET | `/img/<id>/…?v=preview\|result` | تصویر پیش/پس |

همهٔ اعداد σ، blockiness و زمان از خروجی JSON خود `atlas-cli` می‌آیند؛ UI هیچ عددی
را حدس نمی‌زند یا هاردکد نمی‌کند.

## چرا وب و نه Tauri (فعلاً)

Tauri به Rust + WebView سیستمی نیاز دارد و در محیط ساخت فعلی موجود نیست. اما
معماری عمداً طوری است که مهاجرت ارزان باشد: `web/` بدون هیچ تغییر در یک
WebView داخل Tauri اجرا می‌شود و همین `/api/*` با همان `atlas-cli` کار می‌کند.
هسته (C++) در هر دو حالت دست‌نخورده است. جزئیات و محدودیت‌ها:
[../docs/21-desktop-ui.md](../docs/21-desktop-ui.md).
