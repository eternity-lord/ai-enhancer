# ۰۸ — طراحی تجربهٔ کاربری (UI/UX)

اصل: کاربر باید در **۳ کلیک** به نتیجه برسد، و حرفه‌ای باید در **۳۰ ثانیه** همهٔ کنترل‌ها را پیدا کند.

---

## ۱. ساختار کلی (دسکتاپ)

```
┌────────────────────────────────────────────────────────────────────────┐
│  Atlas        [Photo ▾]  [2x 4x 8x]   ⚙ Backend: Auto   ▁▂▃ ۳ صف      │
├──────────────┬─────────────────────────────────────┬───────────────────┤
│  صف کار      │            بوم تصویر                │   پنل تنظیمات     │
│  ┌────────┐  │        (قبل / بعد / اسلایدر)         │  ┌─────────────┐  │
│  │ a.jpg ✓│  │                                     │  │ مدل: Auto ▾ │  │
│  │ b.png ⏳│  │                                     │  │ کیفیت ───●─ │  │
│  │ c.webp │  │                                     │  │ نویز  ──●── │  │
│  └────────┘  │                                     │  │ چهره  [✓]  │  │
│              │                                     │  │ Light ─●── │  │
│  + افزودن    │                                     │  │ پس‌زمینه[ ]│  │
│              │                                     │  └─────────────┘  │
├──────────────┴─────────────────────────────────────┴───────────────────┤
│  [پیش‌نمایش کاشی]   پیشرفت ██████░░ ۴۲٪  ~۲ دقیقه   [Enhance]          │
└────────────────────────────────────────────────────────────────────────┘
```

### تصمیم‌های UX

- **پنل راست، صف چپ، بوم وسط** — همان الگوی LetsEnhance که کاربران می‌شناسند (کاهش هزینهٔ یادگیری).
- **مدل پیش‌فرض Auto** با توضیح کوتاه: «چهره و فشردگی JPEG تشخیص شد → Balanced + Enhance faces».
- **همیشه پیش‌نمایش کاشی** قبل از اجرای کامل (۱ ثانیه، روی ناحیهٔ انتخاب‌شده) — جلوگیری از ۱۰ دقیقه انتظار بی‌فایده.
- **ETA بازه‌ای** (مثلاً «۲ تا ۳ دقیقه») نه عدد قطعی دروغین.
- **هیچ دکمه‌ای بدون بازخورد نیست**: هر تغییر پارامتر → پیش‌نمایش کاشی debounce‌شده (۳۰۰ms).

## ۲. جریان‌های اصلی

### ۲.۱ جریان سریع (۹۰٪ کاربران)

```
فایل را رها کن → مدل Auto → پریست «وب» یا «چاپ» → Enhance → مقایسه → ذخیره
```

### ۲.۲ جریان حرفه‌ای

```
فایل → انتخاب مدل → ماسک/ناحیه → تنظیم شدت‌ها → Try all (۴ مدل)
→ مقایسهٔ کاشی‌به‌کاشی → انتخاب → خروجی ۱۶ بیت TIFF + پروفایل
```

### ۲.۳ جریان دسته‌ای

```
پوشه را رها کن → پریست → بررسی تخمین زمان کل → شروع
→ پیشرفت کلی + خطاها → «بازکردن پوشهٔ خروجی»
```

### ۲.۴ جریان دستیار (اختیاری، ۱.۱+)

```
«این عکس برای چاپ ۵۰×۷۰ می‌خواهم» → دستیار: ابعاد هدف، DPI، مدل، هشدار کیفیت منبع
```

## ۳. پریست‌ها

| پریست | مدل | مقیاس | خروجی | کاربرد |
|---|---|---|---|---|
| Web / سریع | Balanced | ۲x | JPEG q90 | وبلاگ، شبکه اجتماعی |
| Photo Print | Prime-like + face + light | ۴x | TIFF 16-bit, 300DPI | چاپ |
| Product / Text | Gentle + sharpen کم | ۲–۴x | PNG | بسته‌بندی، لیبل، UI |
| Anime / Art | Digital Art | ۴x | PNG | آرت، کامیک |
| Old Photo | Old Photo + face | ۲x + پاس SR | TIFF/JPEG | مرمت |
| Social 4K | Balanced | تا ۴K دقیق | JPEG | بنر/کاور |
| Massive (A+ only) | Ultra/Diffusion | ۴x | PNG/AVIF | بنر غول |

پریست‌ها JSON و قابل اشتراک‌گذاری‌اند؛ یک کلیک «ذخیرهٔ تنظیمات فعلی به‌عنوان پریست».

---

## ۴. مقایسه

- **اسلایدر عمودی/افقی** با زوم همگام (pan/zoom sync) و درصد بزرگ‌نمایی.
- **زوم ۱۰۰٪** با یک کلیک (کلید `1`).
- **Try all**: چهار پنل، همان ناحیه، همان زوم؛ کلیک روی هر پنل = انتخاب آن نتیجه.
- **نقشهٔ اطمینان**: لایهٔ حرارتی که نواحی «توهم‌شده» را نشان می‌دهد (تمایز ما).

---

## ۵. دسترس‌پذیری و RTL

- ناوبری کامل با کیبورد: `Tab` بین مناطق، `Space` پیش‌نمایش، `Enter` اجرا، `Esc` لغو.
- شورتکات‌ها: `Ctrl+O` افزودن، `Ctrl+Enter` اجرا، `Ctrl+Z` بازگردانی پارامتر، `[`/`]` زوم.
- کنتراست WCAG AA، هدف لمسی ≥۴۴px در موبایل، پشتیبانی screen reader با برچسب‌های `aria`.
- **RTL واقعی**: آینه‌سازی چیدمان (نه فقط راست‌چین کردن متن)؛ اعداد و مسیر فایل با جهت LTR.
- فونت فارسی: وزیرمتن/استعداد با fallback؛ ارتفاع خط مناسب فارسی.
- حالت روشن/تاریک/سیستم؛ رنگ‌ها از توکن‌های semantic.

│  │     تصویر       │  │
│  │   (pinch zoom)  │  │

│  کیفیت: ────●───      │

- تنظیمات در **bottom sheet**؛ پیش‌فرض‌های حساس (مثل شدت) با اسلایدر بزرگ.
- پیشرفت در نوتیفیکیشن؛ امکان ادامه در پس‌زمینه (foreground service).
- دکمهٔ «ذخیره در گالری» + «اشتراک‌گذاری» بومی.

## ۷. حالت‌های خالی/خطا/لبه

| وضعیت | پیام پیشنهادی |
|---|---|
| بدون GPU | «روی CPU اجرا می‌شود؛ برای سرعت بیشتر درایور گرافیک را به‌روز کنید.» |

| تصویر بزرگ | «۱۲۵ مگاپیکسل؛ خروجی روی دیسک نوشته می‌شود تا حافظه پر نشود» |
| لایسنس مدل | «این مدل برای استفادهٔ غیرتجاری است. تأیید می‌کنید؟» |
| فایل پشتیبانی‌نشده | «فرمت RAW فعلاً پشتیبانی نمی‌شود؛ پیشنهاد: خروجی TIFF از نرم‌افزار دوربین» |

## ۸. میکروکپی (لحن)

- شفاف، بدون اغراق بازاریابی: «بازسازی می‌کند» نه «جادو می‌کند».
- همیشه محدودیت را بگو: «چهره‌های کوچک‌تر از ۳۲ پیکسل قابل بازسازی مطمئن نیستند».
- هرگز «AI» را به‌عنوان توضیح به‌کار نبر؛ بگو دقیقاً چه کاری کرد.

---

## ۹. i18n و ساختار متن

- کاتالوگ JSON (`en`, `fa` از روز اول)؛ هیچ رشتهٔ hard-coded در کد.
- پشتیبانی از جمع/عدد فارسی و تاریخ شمسی در گزارش‌ها (اختیاری).
- ترجمهٔ اصطلاحات فنی ثابت: Upscale = بزرگ‌نمایی، Enhance = بهبود، Denoise = حذف نویز، Decompress = حذف آرتیفکت.
